# Git 分支浏览器

在 Codex **右侧面板的新标签页入口列表**中加入 **Git**，与文件、侧边聊天、浏览器、终端并列。宿主在工具发现时提供语言信息的情况下，入口显示 **Git 分支**或 **Git Branches**。点击后打开专属 Git 标签页，浏览真实仓库的分支、提交记录和逐文件差异。

入口由 Codex 原生组件绘制。面板内容使用 MCP Apps，自动接收 Codex 的字体、颜色和主题变化；采用紧凑列表、细分隔线和窄面板布局。

## 安装和打开

需要 Git、Python 3.9+，以及支持 MCP thread entrypoints 的 Codex 桌面客户端。开发时核对的客户端附带 Codex 0.154.0-alpha.6.2；旧客户端可能不显示该入口。

解压后运行：

    python3 scripts/install.py

安装器复制到个人 plugins/git-branch-explorer 目录，解析 MCP 启动路径和本机 Codex 数据目录，注册个人插件市场，然后运行 codex plugin add。保留其他插件和已有目录。请使用安装器，让当前客户端正确解析本机路径。无需 npm、第三方 Python 依赖、API Key 或云端服务。

在 Git 项目的现有任务或新任务中，打开右侧面板并点击新标签页按钮，在入口列表选择 **Git**。不需要先发送一条让 Codex 打开插件的消息。

安装或更新后，如果已有窗口的入口列表尚未出现该项，先等正在运行的任务结束，再退出并重新打开 Codex，回到原任务查看。这样可重新加载已安装插件；不需要重建任务或迁移历史记录。当前插件没有用于强制刷新宿主入口列表的接口。

点击入口后，插件按当前调用的任务 ID 自动定位项目仓库，直接显示分支与提交。任务使用 worktree 时优先打开该工作树；目录位于仓库内部时，由 Git 找到仓库根目录。新任务尚未写入历史记录、或旧任务的项目移动过位置时，会读取该任务对应的项目关联。

同一个项目有多个仓库时会列出候选项供选择。无 Git 仓库或未取得项目上下文时，会显示具体原因和路径输入框；可点击刷新重试，也可随时通过顶部的“选择仓库”手动打开。不会扫描整台电脑，也不会拿另一个窗口或最近使用的项目代替当前任务。

尚未发送首条消息的新任务中，客户端可能使用没有项目关联的临时任务打开面板。此时插件无法确认消息状态或项目目录，页面会分两步提示：先确认是否已发送过消息，发送后关闭并重新打开“Git 分支”；取得目录后，再检查 Git 仓库。临时任务没有记录不等于用户没有发送过消息，因此页面显示“待确认”，不会误报“尚未发送”或“没有 Git 仓库”。

能读取到当前任务的消息标记时，页面明确显示“已发送”或“尚未发送”，不读取消息正文。目录已识别但没有 Git 仓库时显示检查路径；目录失效、Git 不可用或查询失败时显示具体错误。可点击“重新检查”或手动打开仓库。

## 功能

- 本地分支与远程跟踪分支按 `/` 组成可折叠文件夹树，显示当前分支和上游领先/落后状态。
- 每个分支可达的提交历史；每页 50 条，继续加载到末尾。
- 每条提交显示本地时区的完整年月日、时分，悬停可查看秒和时区；同时显示绿色新增行数和红色删除行数。
- 提交信息、作者/邮箱字面搜索，以及仅第一父链筛选。
- SHA、作者、日期、完整提交信息与变更文件。
- 逐文件文本 diff；合并提交可选择父提交。
- Codex 主题同步、手动浅色/深色、窄面板分支抽屉和详情返回。
- 统一的主题下拉菜单、细圆角滚动条和线性图标；菜单支持方向键、首字母查找、Enter 选择与 Escape 关闭。长分支名保持单行，悬停可查看全名。
- 工作树、仓库子目录、裸仓库、空仓库和 detached HEAD。
- 常驻「提交」页签中的目录树、文件与目录勾选、暂存标记及逐文件差异；可暂存 / 取消暂存、提交所选文件，或仅提交暂存区。
- 「储藏」页签可保存、查看、应用与删除储藏；查看差异时补充第三父提交中的未跟踪文件。应用恢复暂存状态并保留原记录。
- 在“更改”列表按文件撤回，或点击“全部撤回”。恢复未暂存的修改与删除，保留已暂存内容；新文件先备份再移除。
- 创建本地分支（可选择同时切换）、切换分支、合并分支和删除已合并的本地分支。
- 从已配置的远程获取更新、快进拉取、普通推送，并可设置上游分支。
- 在提交详情中撤销提交：生成反向提交，保留历史；撤销合并提交时选择父提交主线。
- 合并 / 撤销发生冲突时显示冲突文件，可在编辑器解决后暂存并继续，或中止本次操作。

选择分支只改变浏览目标，不 checkout。刷新只重读本地记录，不 fetch。远程分支反映最近一次 fetch 的本地跟踪记录。浅克隆只显示本地已有历史。重命名按删除与新增展示，二进制文件只显示差异提示，单文件 diff 超过 800 KB 会提示截断。

列表时间采用提交者时间。行数统计比较提交与其第一父提交，根提交与空目录比较；二进制文件数量单独标注，不计入文本行数。统计随每页历史批量读取；若统计超时或不可用，仍显示提交记录并提示“统计暂不可用”。

## 分支文件夹

`assets/branch-tree.js` 把 Git 返回的分支按 `/` 分组，保留本地与远程根分组；`origin` 等远程名称自然形成下一层目录。节点用完整分组路径标识，末级节点保留原始分支对象，历史查询与 Git 操作始终使用完整 `ref`。目录按名称自然排序，目录内的分支保留最近提交顺序。不含 `/` 的版本名不会被猜测拆分。

`assets/app.js` 将模型绘制为 ARIA tree。点击文件夹仅改变展开状态，点击末级节点才选择浏览分支；支持方向键、Home/End、Enter/空格及单一 Tab 焦点。目录显示后代分支数量，包含当前分支时显示圆点，完整路径保留在提示和可访问名称中。缩进设有上限，适配窄面板。

展开状态在面板本地存储中按仓库路径分别保存，存储不可用时退回当前页面内存。首次打开展开当前分支的路径，之后保留手动收起状态。完整名称搜索临时展开匹配路径，清空搜索不会改写平时的目录偏好。主题或语言变化保持节点与展开状态，不发起 Git 请求。

## 执行 Git 操作

点击顶部 **提交** 页签查看目录树与底部提交说明。全局工具栏提供 **获取、拉取、推送**；工作区工具栏提供所选文件的撤回、暂存与取消暂存。在日志中，通过 **分支操作** 切换、合并或删除所浏览的分支，**新建分支** 从该分支或提交创建本地分支。提交详情中的 **撤销此提交** 使用 `git revert`。

`commit_selected` 验证预览中的确切路径，在确认后执行字面路径的 `git add` 与 `git commit --only`，包含所选文件的全部当前内容并保留其他文件的 index 内容。原有 `commit` 仍只提交 index。所选提交不用于进行中的合并或撤销；失败后刷新查看暂存状态。

储藏应用使用 `git stash apply --index`，要求工作区干净。储藏按 SHA 定位，删除使用预览对应的 reflog 引用。状态指纹包含储藏 SHA 与引用序号，所以删除旧记录等未改变 stash tip 的操作也会使旧预览失效。

`assets/commit-graph.js` 根据父提交 SHA 布置图线，分页后重算已加载行，字面筛选只画节点。`assets/file-tree.js` 使用 Map 构建目录并计算三态复选框。`assets/diff-view.js` 解析 hunk 行号并对齐修改块，两栏分别整体横向滚动、同步纵向滚动。`assets/workbench.js` 负责页签与面板尺寸，尺寸保存在本地存储。

每次修改会先生成具体预览，显示仓库、目标分支、影响和涉及的文件。只有点击确认才执行。预览有效期 5 分钟；执行前重新检查 HEAD、引用、暂存区及工作区状态，变化时要求刷新和重新确认。同一确认凭据在进程内不会重复执行，操作失败或响应不明确时也不会自动重试。

工作区的 **撤回改动** 只作用于“更改”列表中尚未暂存的内容。部分暂存的文件恢复到暂存区版本，已暂存内容保持不变；如需撤回已暂存的修改，请先取消暂存。**全部撤回** 使用预览时的完整文件列表，新增或修改文件后需重新确认。忽略文件不参与撤回；子模块、嵌套仓库、冲突或目录类型变化需单独处理。

撤回前把每个文件的当前内容保存到该工作树 Git 数据目录下的 `codex-git-explorer/discard-backups/`。未跟踪文件仅移除预览中列出的精确路径，不递归清理目录。完成后在工作区显示备份位置；`manifest.json` 对应原路径、文件模式、符号链接目标与编号 `.data` 内容文件。备份不会自动删除，可据此手动恢复误撤回的内容。备份失败时不开始撤回。

切换、合并、拉取和撤销要求工作区没有未提交更改。拉取仅允许快进，分叉时停止；可先获取更新后自行选择分支合并。删除仅针对已合并到当前分支的本地分支，不提供强制删除、远程删分支、强制推送或硬重置。中止合并 / 撤销会放弃该过程中尚未提交的解决结果，确认页会明确提示。裸仓库仅浏览；已有的变基、cherry-pick 等其他未完成操作需在终端处理后刷新。

写操作使用现有 Git 身份、凭据、签名配置和钩子，不跳过检查。远程操作使用仓库已配置的远程地址；认证或签名需要交互时，可先在终端完成后重试。最长运行时间为 55 秒；超时可能已部分生效，应刷新检查结果。打开面板、浏览历史、刷新以及生成预览均不会自动提交、获取或推送。

## 原生入口实现

`.codex-plugin/plugin.json` 引用 `.mcp.json`，通过 stdio 启动 `scripts/mcp_server.py`。

`git_panel` 工具声明：

```json
{
  "title": "Git",
  "_meta": {
    "ui": { "resourceUri": "ui://git-branch-explorer/v0.5/panel.html" },
    "openai/ui": { "entrypoints": [{ "type": "thread" }] }
  }
}
```

Codex 读取该声明并将工具标题与图标加入侧边面板入口列表。HTML 资源使用 `text/html;profile=mcp-app`，通过 `ui/initialize`、`ui/notifications/tool-result` 和 `tools/call` 与宿主通信。数据查询工具只向面板开放。主题使用宿主提供的 CSS 变量。

MCP UI 的公开基础协议见 [OpenAI 插件 UI 文档](https://developers.openai.com/plugins/build/chatgpt-ui)。`openai/ui.entrypoints` 的 Codex thread 接入方式已根据本机客户端实现核对，其跨版本兼容性仍取决于客户端。

项目定位使用 Codex 在工具调用 `_meta` 中传入的 `threadId` / `thread_id`。`scripts/project_context.py` 只读查询本机 Codex 的任务工作目录，以及桌面端保存的任务与项目关联；这些本地元数据格式已按开发时客户端核对，不是稳定的公开插件 API。格式变化或无对应记录时显示手动选择，不猜测当前项目。独立 MCP 客户端没有传任务 ID 时，才使用进程工作目录。

当前核对的客户端只为内置面板命令提供快捷键注册与入口按键标识，MCP thread entrypoint 没有对应扩展字段。因此此插件尚未提供用于打开面板的应用级快捷键；在标题中写快捷键文字不会产生真实按键绑定。完整支持需要客户端扩展命令注册和入口渲染。

## 语言同步

`assets/i18n.js` 接收 `ui/initialize` 中的 `hostContext.locale`，并响应 `ui/notifications/host-context-changed` 的语言变化。兼容宿主映射到 `document.documentElement.lang` 的语言；没有宿主信息时，使用浏览器语言。英文语言区域显示英文，中文语言区域显示简体中文，其他语言暂时回退为英文。

英文文案集中在 `assets/locales/en.json`，中文源文案作为翻译键。面板只绑定明确标记的界面文字和属性，语言变化时更新原节点，不重建输入控件或操作预览。日期和数字使用当前语言区域的 `Intl` 格式。提交草稿、搜索条件、表单选项和确认凭据保持不变，不因切换语言重新发起 Git 请求。

后端通过 `scripts/i18n.py` 为提示、错误和操作预览保留消息键及参数，以 MCP 结果中的 `gitExplorerMessages` / `gitExplorerError` 元数据传给面板。Git 分支名、作者、提交信息、路径和 diff 属于数据，原样显示；不把它们当作翻译键。独立 HTTP 调试模式使用相同的文案目录和消息标记。

工具元数据使用宿主传入的 `_meta["openai/locale"]`，兼容旧字段 `webplus/i18n`。如果工具发现阶段没有提供语言，原生入口使用通用名称 `Git`；标签标题由宿主绘制和缓存，面板无法强制改名。界面资源 URI 是原生入口的持久化标识，兼容更新保持 `ui://git-branch-explorer/v0.5/panel.html` 不变。Codex 会比较项目中已缓存的入口 URI 与全局新发现的工具 URI；仅让旧 URI 可读不足以保持入口有效，二者必须一致。应用版本通过 manifest、serverInfo 和 appInfo 更新。

宿主 HTML 语言约定见 [OpenAI Widget localization](https://developers.openai.com/plugins/build/chatgpt-ui)，调用方语言元数据见 [OpenAI 插件参考](https://developers.openai.com/plugins/reference)。Codex 的 `hostContext.locale` 接入已按本机客户端代码核对，没有修改客户端文件。

## 数据与运行

原生模式由 Codex 管理 MCP 进程，无需本地网页服务、端口或外部资源。没有遥测。用户确认获取、拉取或推送时连接所选 Git 远程；打开 GitHub 创建流程时通过官方 CLI 查询登录账号和目标仓库名，确认创建后按选项上传。详细数据由 MCP 工具结果元数据提供给面板。Git 命令使用参数数组执行；历史与差异查询禁用外部 diff、textconv、可选锁和懒加载网络请求。

`git_query` 和 `git_prepare` 标记为只读，`git_apply` 明确标记为可写、可能破坏性和可能访问外部。操作工具仅对面板开放；面板通过预览返回的短期凭据确认操作，不接受自由格式的 Git 命令。

`scripts/github_setup.py` 负责非 Git 项目的创建。`github_project` 检查显式目录或查询任务进度；`github_prepare` 使用临时 Git index 计算忽略规则与确切路径，不修改项目，确认凭据有效期为 5 分钟并绑定任务和路径。应用前复核账号 ID、提交身份、文件内容指纹与忽略文件。`github_apply` 在后台创建任务，先初始化与提交，再创建远程并推送；进度查询不会重放写操作。失败保留已有步骤和结果，远程创建请求超时标记为待核实，不能自动重复请求。API 通过 `gh api --hostname github.com` 调用，不处理令牌；新仓库本地配置 gh 的 credential helper，供首次与后续 Git 远程操作使用，不修改全局凭据设置。测试仅使用模拟 API 和本地裸远程。

另保留独立浏览器模式，便于调试或在其他环境中使用：

    python3 scripts/git_explorer.py start --repo "/你的仓库路径"

返回随机会话 URL，服务仅监听 127.0.0.1，两小时无请求会退出。该模式与原生入口分别启动，保留为只读调试模式，操作按钮仅在原生 MCP 面板显示。
